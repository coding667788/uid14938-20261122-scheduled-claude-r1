把下面的设备更新规约做成一套断电可重放的启动验证器。本题的设备是纯文件模拟，分区、签署见证和单调寄存器均为虚构，不接触实际固件。

设备有 A/B 两块区域，每块维护写入代次、页摘要和签名目录。候选镜像的签署清单固定版本号、目标设备组、全部页摘要与授权代次。过程把新页写到非活动分区，经完整读取核对后原子写入 READY；此前可以分批写和恢复同一版本写入，但任何已切换到新代次的分区不得混用旧页。正式引导以只增可信计数器为版本下限，记录哪一个经过复核的分区符合选取规则。切换动作拆成写入候选标记、确认健康、提升计数器、发布活动标记。只有健康回执及签名目录在当前授权下有效，且计数器提升后仍有完整可信可启动副本，才允许写计数器。试运行只允许完整、已读回和当前获签的 READY 镜像进入隔离自检，允许健康确认前的试启，期间不得切入对外服务。晚到的健康回执只适用于对应试启代次。若试启结束前反复断电，重启可回到当时仍符合计数器下限与现行授权的旧镜像；旧镜像已被吊销时须报告安全停机。任何不完整区域都不得作为回退目标。已写完与未来能被可信启动是不同结论。

输入含更新命令、吊销事件、按扇区编号列出的可写页预算和开始状态。一次编程可以只完成日志中声明的任意合法前缀，重启恢复由持久标记读取，计数器和单条标记各自原子，不能假设跨设备原子。replay 对确定轨迹列出可启动分区和证据；check 对给定更新序列验证在输入限定的至多两次断电情形下，从任何前缀恢复对外服务前均已确认所选镜像，同时若有仍可信的正式旧镜像且策略允许要维持可用。返回最短失败轨迹和所依赖页、授权及计数器见证。同一命令重试要核对原申请及分区代次，失败不推进已提交版本。进一步给 repair，从批准的有限修复动作中选择固定的动作顺序使 check 通过，按擦除扇区次数、动作数、ID 序列优化。覆盖计数器提高但活动标记未写、两分区各剩半份、重试混入旧页、试启健康确认迟到及撤销竞态；用小页数穷举对拍并提供 16 个动作和 64 个页的实例。

从空仓库写程序。验收使用 Windows 原生 Python 3.12、内置标准库和 CPU，执行 python -m boot_replay <命令> CASE.json。标准输出须为可重现的 UTF-8 JSON，错误定位到具体字段或事件。交付可直接回放的合成案例、完整 README 和 unittest 测试。
